# Fork Inclusions

Candidate improvements found in upstream pull requests and other PiGallery2 forks, plus relevant fixes already present in this repository's history. Links and PR status checked on 2026-10-06. The merged entries below are reachable from this branch's history.

| Area | Robustness idea | Source | Notes for this fork |
| --- | --- | --- | --- |
| Indexing | Clean malformed `NaN` values from entities before database writes so one image with broken EXIF data cannot repeatedly fail indexing. | [Upstream PR #1166 by Tianpapa](https://github.com/bpatrik/pigallery2/pull/1166) | Open PR. Review the recursive cleanup at the persistence boundary and ensure it preserves dates, buffers, and ORM entity behavior. |
| Previews | Select a preview at least as large as the rendered viewport on high-DPI screens, instead of choosing the numerically closest size. | [Upstream PR #1165 by Tianpapa](https://github.com/bpatrik/pigallery2/pull/1165); [Plus implementation](https://github.com/Railline/pigallery2plus/blob/main/src/frontend/app/ui/gallery/MediaIcon.ts) | Open PR. The Plus fork has a related viewport/DPR-aware selection implementation to compare. |
| Authorization | Check that the requesting user can access the target album when deleting it; the PR reports a possible insecure direct object reference. | [Upstream PR #1173 by tomaioo](https://github.com/bpatrik/pigallery2/pull/1173) | Open PR. Review the reported path and authorization rules independently before adapting the fix. |
| Thumbnail cache | Detect when a file changes while keeping the same path, then invalidate and regenerate its thumbnail. | [Upstream issue #1178](https://github.com/bpatrik/pigallery2/issues/1178) | Open issue; no PR is linked. The report says gallery reset and re-indexing can leave an old thumbnail in place. |
| Thumbnail processing | Bound resource use for very large animated images and recover failed thumbnail placeholders when the source becomes readable. | [Plus image processing](https://github.com/Railline/pigallery2plus/blob/main/src/backend/model/fileaccess/fileprocessing/PhotoProcessing.ts) | Fork implementation, not an upstream PR. Check how its limits interact with this fork's Sharp/libvips pipeline. |
| Cover privacy | Scope folder-cover selection to the requesting user's visible media so a cover cannot reveal an image from a hidden folder. | [Custom fork cover manager](https://github.com/banma1234/pigallery2_custom/blob/master/src/backend/model/database/CoverManager.ts) | Fork implementation, not an upstream PR. Compare with the current session projection and sharing rules. |
| Indexing memory | Trigger garbage collection periodically while scanning large libraries. | [Upstream PR #1071 by evrial](https://github.com/bpatrik/pigallery2/pull/1071) | **Merged** into upstream master on 2025-11-12 and present in this branch's history. A practical memory guard; it does not by itself rule out other indexing memory growth. |
| Random ordering | Use Fisher–Yates for randomized photo order, avoiding the biased results of sort-based shuffling. | [Upstream PR #1131 by infinitejones](https://github.com/bpatrik/pigallery2/pull/1131) | **Merged** into upstream master on 2026-02-08 and present in this branch's history. |
| HEIC media | Correctly handle HEIC image dimensions during media processing. | [Upstream PR #879 by grasdk](https://github.com/bpatrik/pigallery2/pull/879) | **Merged** into upstream master on 2024-04-11 and present in this branch's history. |
| Timestamp parsing | Handle non-standard timezone offsets in media timestamps. | [Upstream PR #1138 by grasdk](https://github.com/bpatrik/pigallery2/pull/1138), [later revert #1157](https://github.com/bpatrik/pigallery2/pull/1157) | **Merged, then reverted**: #1138 merged on 2026-05-16 and #1157 reverted it on 2026-05-30. The original fix is not active in the current history. |

The upstream PRs are proposals and may change before merge. The fork links point to implementation references, not reviewed or approved patches.
